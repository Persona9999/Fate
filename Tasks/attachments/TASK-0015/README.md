## 抽格找到並改掉的

1. 「黑洞後面那一半盤」那行字靠右對齊、被左邊切掉 ⇒ 改成從左邊排。
2. 方塊一開始被本小姐的頭像擋住 ⇒ 換發射的方位角；後來又被讀數板擋住 ⇒ 讀數板往下移。
3. 方塊的標記跑到影子中間：差異的重心把「直接看到的像」和「另一側的重影」平均了 ⇒ 找方塊時關掉重影再相減。
4. 方塊還在 6 rs 的時候讀數就寫「其實它已經進去了」（照座標時間它確實已經過了視界，可是畫面上它明明還在掉）⇒ 改成看到的位置小於 1.6 rs 才寫「看起來停住了 —— 其實早就進去了」。
5. 方塊靠近視界之後暗到看不見，「卡住不動」看不出來 ⇒ 右上角的放大框把曝光調高（最多 300 倍，倍數寫在框下面）；再暗就寫「調亮 300 倍也看不見了」。主畫面的曝光不動。
6. 第二個像原本是一條很細的弧 ⇒ 換成軌道面包含視線的軌道，方塊走到正後方時兩個像連成一圈。
7. 掉到最後整個畫面是黑的（影子超過了視角）⇒ 轉頭之後不轉回來，最後看的是跟墜落方向垂直的那一圈。
8. 漏光的對照：`render()` 用到的「現在念到哪」比畫面慢一格 ⇒ 先算再畫。影子太小看不出斑紋 ⇒ 視角從 140° 收到 100°。
9. 第一次正式錄影有一格卡了 2030 毫秒：切到丟方塊的鏡頭時顯示卡現編著色器 ⇒ 錄影前每個鏡頭先畫一格暖機。重錄之後最慢一格 31 毫秒。
10. 方塊的顏色跟抽格時不一樣（顏色是照發射順序輪的，暖機多發射了幾次）⇒ 每個鏡頭開始時把順序歸零。
11. 片尾最後一行字太長，左右都碰到邊 ⇒ 拆成兩行。

## 重跑

在這個資料夾裡（Git Bash）：

```bash
python -X utf8 tools/tts.py "<ffmpeg.exe>" tools/lines_cn.json site cn        # 念台詞、排時間軸（site/voice_cn/、site/timeline_cn.json）
python -X utf8 tools/asr_check.py timeline site cn                            # 聽寫檢查
python tools/rec.py site "<chrome.exe>" 120 "?measure=1" out_cn               # 只量數字、不錄影
python tools/rec.py site "<chrome.exe>" 240 "?shots=1" out_cn                 # 只抽格（約 10 秒）；?shots=45,48.5 只抽指定的幾格
python -I tools/sheet.py "<ffmpeg.exe>" site/out_cn                           # 抽格拼成總覽圖
bash tools/build.sh                                                           # 正式錄影＋混音＋量音量＋從成片抽格（約 5 分鐘）
```

- ⚠ `rec.py` 這一版會讀環境變數 `REC_PAGE`／`REC_FLAGS`，不要用 `python -I` 跑。
- 改了台詞（句數、順序）要回頭對 `site/intro.html` 的鏡頭表（`defineShots()` 裡的 `at(幾)`）與 `QUIET`。
- 模擬的程式碼有更新時，把 `D:\Unity\BlackHole\js` 的那五個檔重新抄到 `site/bh/`。
