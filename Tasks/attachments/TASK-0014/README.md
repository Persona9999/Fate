# 黑洞模擬網頁（TASK-0014）

一個不用安裝、不用架伺服器的網頁：`site/index.html` 直接點兩下就開（需要支援 WebGL2 的瀏覽器）。

三個場景：

| 場景 | 看什麼 |
|---|---|
| ① 光線彎曲 | 黑洞的影子、被彎到上面來的吸積盤背面、右下角俯視圖上一排平行光各自怎麼彎 |
| ② 物體掉入 | 把發光的立方體（或球）、光束丟進去：速度、方向、質量、形狀都可調；遠處看到它變慢、變紅、變暗、停在視界前 |
| ③ 自己掉入 | 攝影機自由落下，穿過視界，一路算到 0.02 rs；可以轉頭看外面 |

操作：滑鼠拖曳＝繞著黑洞轉（落下時＝轉頭）、Shift 或右鍵拖曳＝轉頭、滾輪＝遠近（落下時＝視角）、按兩下＝看回黑洞；
空白鍵暫停、`1` `2` `3` 換場景、`L` 發射、`F` 落下、`H` 懸停。在右下角俯視圖上按住拖曳＝彈弓發射。

單位：長度是黑洞的史瓦西半徑 rs，時間是 rs/c。「顯示 → 換算成」可以選黑洞的質量，讀數會多出公里、秒，以及潮汐力。

---

## 1. 檔案

```
site/index.html      版面與樣式
site/js/physics.js   物理核心：度規、運動方程式、積分、標架（瀏覽器與 node 共用，不碰畫面）
site/js/selftest.js  物理核心的自我測試（node js/selftest.js）
site/js/shader.js    著色器：每個像素往回追一條光線
site/js/renderer.js  WebGL2：把「畫面描述」交給著色器
site/js/camera.js    觀察者：懸停／自由落下／到奇異點
site/js/bodies.js    拋進去的東西：軌跡、看到的位置、交給著色器的資料
site/js/map2d.js     右下角的俯視圖
site/js/app.js       介面、場景、畫面迴圈、用顯示卡算的自我測試
tools/serve.py       開發用的本機伺服器（不快取）。平常用不到。
```

分層的原則：**物理只寫在 `physics.js` 與 `shader.js` 兩個地方**（同一組方程式各一份，CPU 算物體與攝影機、GPU 算光線），
其他檔案不懂物理。要換度規（自旋、多洞）就是改這兩份。

## 2. 物理是怎麼算的

- **座標**：Kerr–Schild 形式（直角座標 x、y、z ＋ 向內的 Eddington–Finkelstein 時間 t）。
  `g_{μν} = η_{μν} + f l_μ l_ν`，史瓦西是 `f = rs/r`、`l_μ = (n, 1)`。這套座標在視界上是正常的，
  所以物體與攝影機可以一路算進視界裡面，不用換座標。
- **運動方程式**：哈密頓量 `H = ½ g^{μν} p_μ p_ν = ½(|p|² − p_t²) − ½ Σ f L²`，`L = n·p − p_t`。
  有質量的粒子 H = −½，光 H = 0。四階 Runge–Kutta。
- **攝影機**：每一格在攝影機的位置對度規做 Gram–Schmidt，得到它自己的局部標架（先對 4-速度投影，光行差就在裡面）；
  每個像素的方向換成光的動量，沿零測地線**往過去**追，直到飛到遠處（查天空）、貼到視界（黑）、
  或中途碰到吸積盤／物體。
- **物體**：發射時把整條測地線算好，存成一列浮點貼圖。光線自己帶著座標時間往回走，
  用「光經過那裡的那一刻」去查物體在哪 —— **光行時間差本來就在裡面**，
  「遠處看物體凍結在視界前」不是另外做的效果，是算出來的。
- **顏色**：吸積盤與物體的顏色用 `g = 觀察到的頻率 ÷ 發出的頻率 = 1/(p·u)` 調（都卜勒＋重力紅移）；
  盤的亮度乘 g⁴。色彩映射是示意（黑體色溫近似），不是光譜計算。

### 哪些是精確的、哪些是近似

| 項目 | 狀況 |
|---|---|
| 光線路徑、影子形狀、物體與攝影機的軌跡 | 史瓦西度規的測地線，數值積分；有自我測試對解析值 |
| 物體的光行時間差、凍結、時間變慢 | 直接由光線的座標時間算出，沒有另外加效果 |
| 吸積盤 | 幾何薄盤的溫度分布＋克卜勒轉速；「厚度」與雲的紋理是**美術**，不是流體模擬 |
| 物體的質量 | 測試粒子：路徑不看質量。質量只影響畫出來的大小、與「黑洞吃了變重」長多少 |
| 黑洞吃了物體變重 | 近似：物體過視界那一刻 rs 瞬間變大，其他東西從當下的位置與動量重算。真實情況不是瞬間的 |
| 攝影機的標架 | 每一格重新對著黑洞做，不是平行移動。徑向落下時兩者相同；帶角動量落下時等於一直把頭轉向黑洞 |
| 俯視圖上「你此刻看到的位置」 | 光行時間用「直線距離＋徑向光在視界附近多花的時間」估計；主畫面不用這個估計 |
| 星空、銀河 | 程序產生的，不是真的星表 |

## 5. 預留：多黑洞、自旋、融合（現在都沒做）

架構上留的位置，以及接下去會撞到什麼：

### 多黑洞（雙黑洞以上）
- **已經有的**：`holes` 是陣列；`physics.js` 的 `rhs`、`metricInv` 與著色器的 `rhs`、`stepLen`、抓捕判斷都對洞做迴圈
  （著色器的洞數上限是編譯期常數 `MAX_HOLES`，renderer 照 `holes.length` 現編）。
- **那是什麼近似**：把每個洞的 `f l l` 項直接加起來（Kerr–Schild 疊加）。它不是愛因斯坦方程式的解；
  兩個洞離得遠時是好的近似，靠近時不準。**沒有驗證過**。
- **要補的**：
  1. 介面與場景（現在只開放一個洞）。
  2. `shader.js` 的「用守恆量判斷」那條捷徑（`uEnergyTest`）只對單一靜態洞成立，多洞時要關掉 ——
     關掉之後，貼近視界的畫面會漏光（自我測試裡有量：同一格 1152 個像素）。要換別的做法，
     例如貼近視界時改用正規化過的變數積分，或把抓捕半徑放寬。
  3. 吸積盤、俯視圖的光行時間估計、攝影機「看向黑洞」都只認第 0 個洞。

### 自旋（Kerr）
- Kerr 在 Kerr–Schild 形式下只是換一組 `f` 與 `l`：
  `f = rs r³/(r⁴ + a² z²)`、`l = ((r x + a y)/(r² + a²), (r y − a x)/(r² + a²), z/r, 1)`，r 由隱式方程式解。
  要改的地方就是 `physics.js` 的 `rhs`／`metricInv` 與 `shader.js` 的 `rhs`（兩處都有註解標出來）。
- `hole.spin` 欄位、著色器的 `uHoleSpin` 已經在，但沒人讀；`hole.model = 'kerr'` 會被 `validateHoles` 擋下。
- **要補的**：`f`、`l` 對位置的導數（解析或差分）、視界半徑不再是 rs、
  `uEnergyTest` 的判斷要換（守恆量變成 E 與 L_z，再加 Carter 常數）、吸積盤的轉速與內緣（ISCO 隨自旋變）。

### 融合
- 需要會動的洞與隨時間變的度規。現在 `rhs` 假設度規不隨時間變（`dp_t/dλ = 0`、光線的 p_t 不更新）。
- **已經有的**：`hole.vel` 欄位；光線本來就帶著座標時間往回走；
  「度規變了之後，把還在飛的東西接到新的度規上」這條路已經走通（`bodies.replan`、`camera.renormalize`、
  `physics.normalizeMomentum`，現在給「黑洞吃了變重」用）。
- **要補的**：洞的位置寫成時間的函數（著色器裡要能查「光線那一刻洞在哪」，可以比照物體的軌跡貼圖）、
  `rhs` 的時間導數項、融合後的單一洞（質量與自旋）與重力波帶走的能量——這些要從數值相對論的結果查表，
  疊加近似在融合那一刻完全不適用。

## 6. 已知的限制

- 物體是測試粒子，彼此不互相吸引，也不會撞到吸積盤。
- 物體的像只在「攝影機此刻看到它的那個時刻」前後一段時間內找；離黑洞很遠的物體，
  繞過黑洞才到的第二個像（很小）可能不畫。
- 「黑洞吃了變重」之後，面板上的滑桿讀數會除以新的 rs 顯示，但滑桿本身還是原本的長度單位。
- 攝影機在視界內時，俯視圖的「看到的位置」只用直線距離估計。
- 很靠近奇異點（r < 0.02 rs）不算。

## 7. 這一版改動過程中抓到的錯（都已修）

| 症狀 | 原因 | 怎麼確認修好 |
|---|---|---|
| 換場景之後「物體／光束」按鈕失效 | 場景把拋射器的設定物件整個換掉，按鈕還抓著舊的 | 實際點按鈕發射光束：物體數 3 → 8（5 顆光子） |
| 「擦過光子球」的光卻掉進去了 | 發射方向用了座標上的角度，不是當地懸停的人量到的角度 | 設定 b = 1.03 b_c，量到 1.03000 b_c，飛走、最近 1.756 rs |
| 落下時影子裡出現白色斑紋（Tim 截圖） | 光線貼近視界時動量發散，單精度的 RK4 跨過去會算出垃圾，漏到天空 | 自我測試「貼著視界外（1.02 rs）」：1152 → 0；落下途中 3.2 rs 到 0.5 rs 抽 11 處，影子內亮點都是 0 |
| 物體「變成好幾顆」 | **不是錯**：重力透鏡的第二個像。量過單一物體穩定是 2 個像（大的在一側、小的在影子另一側） | 面板加了「畫出重影」開關與說明 |
