# TASK-0011 — 跨主機連線（第一版）：WebSocket 傳輸、Discord 交換位址、Cloudflare 臨時通道當退路 —— 在線名單與酒館訊息串接

> `feature` / `normal` / `in_progress`　開單：Claude-Ojousama　參與：Claude-Ojousama(dev)

## 驗收標準

Tim 2026-11-11：「傳輸用 WebSocket，位址用 Discord 交換，連不進去時用 Cloudflare 臨時通道補 先嘗試這個方案做一版本看看吧」。用途：看在線同事時包含另一邊的在線；酒館訊息直接送到另一端、讀到另一端的訊息，不用靠 Discord 同步。

Tim 2026-11-11（動工後追加）：「走 Discord 配對 可以讓一端當主機（從後台介面啟動） 主機發送訊息到 Discord 另一端收到 Discord inbound 訊息後就能連線到主機（連上後發送酒館訊息都是送到主機 然後由主機轉發）」。⇒ 配對改成「主機公告」，不做配對碼。

- [x] 主機：從後台頁（或指令）啟動後開始收連線，並產生公告（位址＋這一場的 token＋公鑰）　✅ Claude-Ojousama 2026-11-11
- [x] 連線：另一端照公告用 WebSocket 連上主機；另一端證明看得到公告、主機證明自己是貼公告的那一台；斷線會自動重連　✅ Claude-Ojousama 2026-11-11
- [x] 在線名單：酒館追讀列得出另一台主機在線的人，並標明是哪一台；連線斷了標成不知道　✅ Claude-Ojousama 2026-11-11
- [x] 酒館訊息：這一邊發的訊息另一邊讀得到（拿另一邊自己的 seq、帶來源主機與原 seq）；另一端的訊息由主機轉給其他另一端；重連後從游標補，不重複　✅ Claude-Ojousama 2026-11-11
- [x] 轉進來的訊息不再轉發回原節點（不迴圈）、不發薪、不觸發酒保　✅ Claude-Ojousama 2026-11-11
- [x] 反向對照：token 不對的一端連不上、訊息一則都沒進來；對面不是貼公告的那一台就不連；同一則訊息重送只落一則　✅ Claude-Ojousama 2026-11-11
- [x] 文件：用法寫成一份，`senate cmd doc` 查得到　✅ Claude-Ojousama 2026-11-11
- [x] 實地：主機的公告真的貼進 Discord 頻道，另一台的 Discord Inbound 收到後自動連上（兩台實體機器）　✅ Claude-Ojousama 2026-11-11
- [ ] 實地：主機在 NAT 後面時開 Cloudflare 臨時通道，另一台經通道連上（沒裝 cloudflared 時會說出來，這一半已由自我測試驗到）
- [ ] 實地：後台頁在視窗裡按「啟動主機」「當另一端」「關閉」各一次，現況跟著變
