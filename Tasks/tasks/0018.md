## 驗收標準

Tim 2026-11-13：「黑洞模擬專案 加一個主選單吧 目前希望可以做另一種模式 是在黑洞附近的太空戰鬥遊戲(主選單可以選取模式 目前模式是黑洞模擬)」

- [ ] 打開網頁先看到主選單，可以選「黑洞模擬」或「太空戰鬥」；兩個模式裡都回得到主選單
- [ ] 原本的黑洞模擬照舊：四個場景、`?scene=`、`?selftest=1` 都還能用，舊的自我測試項目一項都沒少、沒過 0
- [ ] 太空戰鬥：玩家開餘暉號，有推進（會改變軌道）、轉向、開火；有敵機、有命中與血量、有輸贏（掉進黑洞或被打爆算輸）
- [ ] 戰鬥裡的東西照同一套物理走：船受黑洞重力、光束走零測地線（會被彎）、畫面仍然是光線追蹤（透鏡、紅移、光行時間差都在）
- [ ] 自我測試補上遊戲核心：推進（對解析值）、命中判定、瞄準解；每一類至少一項反向對照
- [ ] 反向對照：把推進關掉 ⇒ 船走的就是原本的測地線（跟物理核心算的同一條）
- [ ] 實際在瀏覽器裡玩過一輪（開火、命中、被擊中、結束畫面），附截圖與幀時間讀數
- [ ] README 與設計文件寫明哪些是物理、哪些是遊戲設定

2026-11-13 下午（Claude-Ojousama）：Tim 試玩後回報「目前雷射光束會出現接縫 是否可以優化」（附截圖）。修在 `feat/combat` 的 `7f65058`（接在 `2f2acc8` 後面；還沒合併、沒推）。

量到的來源：
1. 每一段光束固定 0.6（外面的鐘），到下一發的間隔是 0.55 × 船的時間流速 ＋ 一格（r = 9 的軌道上實測 0.640）⇒ 每個接頭空 0.04。
2. 光線分段的交界上，相鄰兩小段都把那一點丟掉 ⇒ 一條暗線。
3. 補測試時抓到：交界上有一截光被「有沒有被擋住」的比較吃掉（少一半亮度）。

改法：光束持續時間改照船自己的鐘；連續開火時一段接一段（上一段的最後一顆光子 ＝ 下一段的第一顆）；還在射的那一段尾端每一格換成當下射出去的光子；
著色器求交做兩遍，交界與接頭兩邊各算一部分。

讀數：node 89 項、瀏覽器 120 項，沒過 0。三段接起來、跨過交界的光束，沿線最暗 ÷ 中間值 0.988、最亮 ÷ 中間值 1.000（修之前同一個量法在交界掉到 0.75）；不接、留空隙的反向對照 0.06。
遊戲裡按住開火又轉頭（r = 6.4）：11 段全部接上，每段持續時間 − 到下一段的間隔 = 0。自動對戰 2,600 格沒有錯誤（第四波、擊毀 5 艘）。

沒動的：能量用完之後光束會變成一節一節（一發 9、每單位時間回 7 ⇒ 射 0.6 停 0.69），那是能量規則，不是接縫；要不要改成按住就一直是連續的，等 Tim 說。
