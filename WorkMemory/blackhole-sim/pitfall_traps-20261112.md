做黑洞模擬時實際踩到、重來會痛的（2026-11-12）：

1. 🩸 **光線貼近視界時單精度的積分會漏光。** 往回追的光線接近視界，動量會發散（∝ 1/(r − rs)），
   RK4 一步跨過那一點就算出垃圾，光線「逃」到天空 ⇒ 影子裡出現白色斑紋（Tim 截圖抓到的）。
   攝影機在 1.2 rs 以外看不出來，貼著視界（1.01～1.1 rs）往下掉時最明顯：512 見方的圖裡 1152 個像素。
   現在的解法是用守恆量（能量 E、角動量 L ⇒ 撞擊參數 b 對 b_c）直接判斷這道光到不到得了天空，
   到不了的就算數值上逃走也算黑，而且路徑一違反「該有的樣子」就停。
   ⚠ 這條捷徑只對單一、靜態、不自旋的洞成立。做多洞或自旋時要關掉（`uEnergyTest = 0`），漏光會回來，要另外想辦法。

2. 🩸 **發射方向要用「當地懸停的人量到的角度」，不是座標上的角度。** Kerr–Schild 座標的徑向長度在當地要除以 √(1 − rs/r)。
   一開始用座標角度，「擦過光子球」的預設反而掉進去。撞擊參數 b = r sin(α) / √(1 − rs/r) 的 α 是當地角度。

3. 🩸 **物體的像要用「光經過那裡的那一刻」的位置畫。** 用的座標時間在視界上是有限的，
   如果用「現在」的位置畫，遠處的人會看到物體直接穿過視界 —— 錯的。凍結來自光爬出來要花的時間。

4. **一個物體看到兩個像不是 bug。** 量過：單一物體穩定是 2 個像（直接看到的＋光繞過黑洞另一側的）。
   Tim 第一眼也以為畫錯。介面有「畫出重影」開關與說明。

5. **瀏覽器面板量到的 fps 不可靠**（面板不在前景時會被節流）。要知道顯示卡實際花多久，
   用 `gl.finish()`＋`readPixels` 自己量：1123×846、RTX 2060，薄盤約 3 ms、體積盤 8～11 ms、8 個物體約 4 ms。

6. python 內建的 http.server 不送 Cache-Control，瀏覽器會拿舊的 js ⇒ 改了著色器看起來沒變。
   用 `tools/serve.py`（no-store）；已經被快取的要先 `fetch(url, {cache: 'reload'})` 一次。

7. 設定物件不能整個換掉：面板的按鈕在建立時抓住了 `S.launcher` 這個物件，
   換場景時 `S.launcher = {...}` 會讓按鈕全部失效 ⇒ 用 `Object.assign`。
